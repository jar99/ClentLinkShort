Clent.

A link shortener with no database, no accounts and no logging. The destination is compressed and packed into the short link, so nothing is ever stored — the link is the entire record, and it works forever.

How it stays stateless

  • Tracking parameters go first. On real shared links this is usually the single biggest saving, and it's the only step that changes the destination.
  • The URL is canonicalised — the scheme, a www. prefix and a trailing slash become single bits in a 6-bit header rather than the 12 characters they normally cost.
  • Around 160 common hosts (github.com, youtube.com, …) collapse to one byte via a built-in dictionary.
  • The rest is encoded three ways — 6-bit text packing, raw bytes, and DEFLATE — and the shortest one wins. Text packing writes each URL character straight into the Base64url alphabet, so ordinary lowercase URLs come out at one character per character with no expansion at all.
  • The payload rides in the fragment (#…), which browsers never send to a server. GitHub's servers, and mine, never see where you're going.

Honest limitations

  • With no database, the link cannot be shorter than the information it carries. Long URLs compress well; already-short ones will come out longer. The counter above tells you the truth either way.
  • Links can't be edited or revoked after sharing — there's nothing to edit.
  • Add ~ to the end of any Clent link to see its destination instead of following it.
No cookies, no localStorage, no analytics, no network requests. Reload with JavaScript disabled and the page does nothing at all — which is the point.
