Clent

A link shortener that stores nothing.

No database, no accounts, no logging — not because they're switched off, but because there is nowhere for them to be. The destination is compressed into the link itself, so the link is the record. It can't expire, can't be revoked, and can't be mined.

    How it works

    1. Tracking parameters go first. Worth about a third of the payload on a newsletter or social link. It's the only step that changes the destination rather than just re-encoding it, which is why it's a visible switch.
    2. The URL is canonicalised. The scheme, a www. prefix and a trailing slash become single bits in a 6-bit header instead of the twelve characters they normally cost.
    3. Common hosts collapse to one byte. A built-in dictionary of 165 hosts turns en.wikipedia.org into 8 bits.
    4. The rest is encoded three ways and the shortest wins. Text packing writes each character straight into the Base64url alphabet at 6 bits — and since Base64 is also 6 bits per character, an ordinary lowercase URL survives at one character per character with no expansion at all. Encoding naively as bytes-then-Base64 costs 1.33× instead.
    5. The payload rides in the fragment — the part after #, which browsers never send to a server. GitHub's servers, and mine, never see where you're going. 
    6 bits  header   scheme · www · dictionary · body mode
8 bits  host     dictionary index, when the host is known
  body  text6    6-bit symbols, terminated by END
        raw      UTF-8 bytes, 8 bits each
        deflate  DEFLATE-raw bytes, 8 bits each

    What it can't do

    • A link can never be shorter than the information it carries. That's arithmetic, not an implementation detail. Long, parameter-heavy URLs compress well; already-terse ones come out longer. The counter above always tells you which happened.
    • Links can't be edited or revoked once shared. There's nothing to edit.
    • Fixed overhead is the domain. Every link carries this site's origin, so a short domain saves more than any further work on the codec would.
    • No click counts, no dashboards, no expiry. All of those need a server that remembers, which is the thing being avoided.
