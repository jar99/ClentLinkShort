    Is it actually shorter?

    Usually not, and it's worth being straight about that. The encoded destination is {{medianPct}} of the URL it came from, but every link also carries this site's address, which is {{originLength}} characters before the payload even starts. A URL has to be longer than about {{breakEven}} characters before that trade comes out ahead.

    Most URLs aren't. Of the {{checked}} tested, {{linkShorter}} produce a shorter link on this domain. The ones that do are the ones people actually run through a shortener: tracking-laden campaign links, document links, anything with a session token in it. The counter above tells you which kind you pasted.

    A shorter domain moves that threshold more than the encoding can. On clent.link the break-even would be around {{shortBreakEven}} characters instead. What you get regardless is a link that nothing is storing and that will still work when this page is gone.

    What's in the link

      Encodings tried

      All three are built for every link. The shortest one is used.

      Tested on real URLs

      The test corpus is {{checked}} URLs taken from Wikipedia citations across 30 language editions, Hacker News submissions, and the Tranco domain ranking. Real URLs are messier than invented ones: doubled slashes, unencoded spaces, mojibake, kilobyte query strings, session tokens, punycode.

      Known links get much shorter

      A lot of shared links are one site's URL scheme with an ID dropped into it. youtube.com/watch?v=dQw4w9WgXcQ is 43 characters, of which 11 carry any information. About 40 shapes are recognised — YouTube, Amazon, imgur, X, Facebook, Instagram, Reddit, TikTok, GitHub, Spotify and more — and for those only the ID is stored, at the exact width its own alphabet needs.

      43 → 15youtube.com/watch?v=…
      36 → 14amazon.com/dp/…
      31 → 11i.imgur.com/….jpg
      40 → 15instagram.com/p/…

      A shape is only used when substituting the captured ID back in reproduces the original URL character for character. A near miss falls back to the general encoder rather than guessing.

      Tamper checks

      Every link gets a four-character check by default. If a link is clipped by a chat app or edited in transit, opening it says so instead of taking you somewhere you weren't sent.

      That check has no key, so anyone can recompute it — it catches accidents, not attackers, and it isn't described as anything more. For more than that, sign a link with a passphrase: 18 extra characters, and whoever opens it can confirm it was made by someone who knows the same passphrase. That proves membership of whoever shares that passphrase, not a particular person, and says nothing about whether the destination is safe.

      How it works

      1. Tracking parameters are removed. On a link that has them, this is worth about a third of the payload. It's the one step that changes where the link goes, so it's a switch rather than a default.
      2. The predictable parts become bits. The scheme, a www. prefix and a trailing slash cost twelve characters in a normal URL. Here they're three bits in a 6-bit header.
      3. {{hostCount}} common hosts collapse to one byte. en.wikipedia.org becomes 8 bits.
      4. The rest is encoded three ways, and the shortest is kept. Text is Huffman-coded: each character costs what its real frequency in URLs earns it — / and e under 5 bits, rare ones more — with a 128-entry table of whole runs like .com, article and /index coded as single symbols. The code was measured from the test corpus, not guessed.
      5. The payload goes after the #. Browsers don't send that part to servers, so no server sees the destination. 
      6 bits  header   scheme · www · dictionary · body mode
8 bits  host     dictionary index, when the host is known
  body  text     Huffman symbols: literals, tokens, escapes, END
        raw      UTF-8 bytes, 8 bits each
        deflate  DEFLATE-raw bytes, 8 bits each

      Safety

      A redirector is useful to a phisher: the link wears this domain, and you can't see where it goes until you're already there. Two things are done about that.

      • Only http and https are followed automatically. javascript: and data: links are refused outright, both when making a link and when opening one.
      • Links with a phishing shape stop and show you the destination first. An address like paypal.com@evil.example goes to evil.example, not PayPal. So do names spelled with lookalike characters, and links pointing at a bare IP address.

      That isn't a judgement about whether a site is dangerous, which can't be known from a URL. It's that ordinary links almost never look like that.

      Limits

      • It isn't a shortener for most URLs. See above: below about {{breakEven}} characters the link comes out longer than what you pasted.
      • Links can't be edited or revoked after you share them.
      • Every link includes this site's domain. That's fixed overhead, and a shorter domain would save more than any further work on the encoding.
      • No click counts and no expiry. Both need a server that remembers.
